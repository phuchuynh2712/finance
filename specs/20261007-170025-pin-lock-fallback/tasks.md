# Tasks: App Lock to the Banking Security Standard (Inactivity Lock and PIN Fallback)

**Input**: Design documents from `specs/20261007-170025-pin-lock-fallback/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/](./contracts/), [quickstart.md](./quickstart.md)

**Tests**: Included. Constitution Principle II requires tests in the same pull request as the behavior, and every new screen needs widget coverage at a compact (412 × 915) and an expanded (1440 × 900) viewport. Pure logic (policy, PIN rules, hasher, verify sequence, flow state machine, channel codec) gets unit tests; time is tested with `fakeAsync` and an injected clock, never with real waiting.

**Organization**: One phase per user story, in spec priority order: US1 (P1, MVP, inactivity lock, every platform) → US2 (P1, unlock with a PIN) → US3 (P1, set up a PIN) → US4 (P1, wrong, forgotten and expired PINs) → US5 (P2, change or turn off) → US6 (P2, the one-time offer). **US1 and US2–US6 are independent of each other** (plan.md, Delivery slices): they ship as two pull requests from `origin/master`, each passing the gate alone. Inside the PIN slice the order is the dependency order (repository and widgets in US2, the flow in US3, and so on).

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on incomplete tasks)
- **[Story]**: US1–US6 (Setup, Foundational and Polish phases carry no story label)
- File paths are exact, per plan.md's Project Structure

## Path Conventions

Single Flutter project (existing structure). Commands run from the repository root `/Users/phuchuynh/finance`.

**Format rule**: run `dart format <file>` on every file you create or edit, so `dart format --output=none --set-exit-if-changed lib test` stays at exit 0.

**New-text rule**: every new string is in `lib/core/l10n/app_vi.arb` and `app_en.arb` (the keys are listed in `contracts/pin-ui.md` §6), with an `@key` description, regenerated by `flutter gen-l10n`, and listed in `test/unit/core/l10n/l10n_key_parity_test.dart`. No literal Vietnamese or English in a widget.

**Widget-test rule**: `test/flutter_test_config.dart` pins the default view to 410 × 864. Every adaptive test sets its own size with `tester.view.physicalSize`, `devicePixelRatio = 1.0` and `addTearDown(tester.view.reset)`. Load the real font with `test/support/load_app_fonts.dart` in any test that checks horizontal fit (the test font is twice as wide as Lexend).

**Existing-tests rule**: the existing sign-in, sign-up, Security and shell tests pass **unmodified**: the PIN panel, row and offer only appear when the PIN is available and active. The only existing test that is rewritten is `test/unit/core/auth/app_lifecycle_observer_test.dart` (T009), because the function it tests is replaced; its pull-request description says so.

**Secure-storage rule**: tests use `FlutterSecureStorage.setMockInitialValues({...})` (it exists in the pinned 9.2.4) and construct the repository with the storage as a constructor argument.

**Pull-request description rule** (constitution Development Workflow): each pull request lists its `core/` changes. PR 1: `core/auth/{app_lock_policy,activity_tracker,lock_channel*}.dart`, `app_lifecycle_observer.dart`, `auth_state_provider.dart`, `lib/main.dart`, `pubspec.yaml` (`web`). PR 2: `core/auth/{pin_rules,pin_hasher,pin_lock_repository}.dart`, `auth_state_provider.dart`, `auth_repository.dart`, `core/router/app_router.dart` (the PIN flow route, T044), `core/l10n`, `pubspec.yaml` (`crypto`).

**Verification rule**: throwaway Playwright and adb/simctl scripts live in the session scratchpad (never committed). The QA account is read from `.env.test-credentials` inside the script and never printed; **setting a PIN needs that password once, and nothing here changes it**; `.env`'s database and service keys are never read; the real project's data is only read: **no task writes to it** (a check that needs a change in the data is done with a fake in a test instead). Results go into `specs/20261007-170025-pin-lock-fallback/verification/README.md` as text. **No screenshots are committed**: view them, then delete the PNGs.

**Android/iOS tool-churn note**: building for iOS or Android can modify tracked platform files; restore with `git checkout -- ios android` before committing.

## Dependencies & Execution Order

### Phase dependencies

- **Setup (Phase 1)** → **Foundational (Phase 2)** → the two slices, which do not depend on each other:
  - **Slice 1**: US1 (Phase 3).
  - **Slice 2**: US2 → US3 → US4 → US5 → US6 (Phases 4–8), in order (US3 needs US2's repository and widgets; US4 needs US2's lock-screen panel and US3's flow for the "offer → set up" path; US5 extends US3's controller and screen; US6 extends US4's dialog).

Tests first and failing → pure logic → repositories and providers → widgets → screens → verification → gate.
